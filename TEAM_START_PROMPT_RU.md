# EVERREALM — общий стартовый промпт для команды ИИ

Ты работаешь над проектом EVERREALM в команде. Главный разработчик просит держать актуальные исходники, проектные решения, промпты, отчёты и передачи в одном общем источнике: [GitHub-репозитории moneyandprogectx-spec/Everrealm](https://github.com/moneyandprogectx-spec/Everrealm). Не создавай дополнительные полные копии проекта без необходимости.

## 1. Сначала установи доступ и актуальную версию

1. Открой репозиторий по ссылке выше и проверь его содержимое. Не полагайся на память из чата.
2. Если у тебя есть локальный Git checkout, проверь его адрес `git remote -v`, ветку, `git status --short` и наличие чужих изменений до любой записи.
3. Если Git checkout недоступен, используй GitHub через доступный официальный коннектор/интерфейс. Если для чтения нужен ZIP, скачай только архив, который действительно присутствует в репозитории, распакуй в отдельную временную папку и прочитай инструкции внутри. Не утверждай, что архив существует, пока не проверил список файлов.
4. Сообщи коротко, что фактически доступно: репозиторий/ветка или архив, точная версия (commit SHA, если виден), прочитанные документы и ограничения доступа. Если доступа нет — остановись до изменений и верни `NO_REPO_ACCESS`.

## 2. Прочитай общие правила и свою роль

Перед началом задачи прочитай в репозитории, если эти файлы присутствуют:

- `AI_STORAGE_POLICY_RU.md` — где хранить материалы и как экономить место;
- `TEAM_START_PROMPT_RU.md` — этот стартовый порядок;
- `Everrealm_Library/PROJECT_STATUS.md`;
- `Everrealm_Library/TASK_REGISTRY.md`;
- `Everrealm_Library/DECISIONS.md`;
- `Everrealm_Library/ASSET_REGISTRY.md`;
- актуальный мастер-промпт и handoff в `Everrealm_Library/AI_Collaboration/`;
- только свой ролевой промпт из `Everrealm_Library/AI_Collaboration/START_2026-11-10/03_MASTER_PROMPTS_V3/roles/`.

Если эти канонические файлы отсутствуют в текущем репозитории/архиве, не выдумывай их содержимое. Укажи, чего не хватает, и используй лишь явно доступные инструкции. Для несовпадающего состояния сообщи о расхождении; не перезаписывай его локально скачанной копией автоматически.

## 3. Личная роль и лимит работы

Главный координатор выдаёт тебе персональный бриф: `ROLE`, `TASK_ID`, `OWNER`, `WORKTREE`, `BRANCH`, `ALLOWED_FILES`, `DELIVERABLE`, `ACCEPTANCE`, `QUOTA_CLASS`. Выполняй только назначенную часть. Не забирай чужую задачу и не редактируй одни и те же файлы параллельно с другим участником.

У каждой модели/сессии собственный ролевой промпт и выделенная квота. Координатор назначает и фиксирует бюджет задачи перед запуском с учётом текущего лимита соответствующей модели/аккаунта; не придумывай универсальное число токенов или сообщений и не расходуй квоту других ролей. Если назначение или бюджет не выданы, сделай только доступное чтение/ревью, подготовь краткую оценку и запроси координацию — не начинай production-правки.

Один `TASK_ID` — одна независимо проверяемая задача. Изменяющие исполнители работают в отдельных ветках/worktrees, как требует проект. Для параллельной работы нужны разные файлы и владельцы. Любые изменения общего состояния проходят ревью, тесты и handoff.

## 4. Храни результаты в общем источнике

Рабочие исходники, решения, промпты, относящиеся к проекту, подтверждённые артефакты и handoff должны попадать в соответствующие папки общего репозитория. Не оставляй единственный результат на локальном диске или в переписке.

- Изменяй только назначенные файлы и только в выделенной ветке. Не делай прямую запись в `main`, если отдельный процесс проекта этого не разрешает.
- Перед передачей сохрани файлы в Git и сообщи ветку/commit SHA или точный путь и состояние, если коммит/публикация недоступны.
- Не выполняй широкую очистку, массовую синхронизацию или замену локальных данных архивом. Не удаляй существующие worktrees, чужие правки или оригиналы.
- Не добавляй тяжёлые кэши, временные сборки, повторные ZIP и рендеры, если они не нужны для воспроизводимости или доставки. Для больших файлов следуй принятому в проекте способу хранения; не предполагай, что GitHub автоматически заменяет рабочий диск или резервную копию.
- Никогда не загружай секреты, приватные данные и чужие игровые ресурсы с неясными правами. Следуй реестру лицензий и правилам проекта.

## 5. Постоянная передача между участниками

После каждой существенной задачи обнови handoff в канонической папке проекта. Он должен включать: исходный commit/версию, роль и TASK_ID, файлы и изменения, реальные проверки и логи, визуальную и лицензионную оценку, ограничения/незакрытые вопросы, ветку/commit SHA, следующего владельца и конкретный следующий шаг. Отличай `DONE`, `PARTIAL`, `BLOCKED`; план не равен выполненной работе.

Промпты, общие для команды, храни отдельно от ролевых. При изменении общих правил обновляй соответствующие ссылки/индекс только по назначению. Не отправляй результаты в чужие аккаунты автоматически: handoff в репозитории — общая передача.

## 6. Первый ответ новой сессии

Начни с короткого отчёта:

- `ROLE` и подтверждённый режим/модель;
- фактически доступный репозиторий, branch/commit или архив;
- прочитанные общие и индивидуальные инструкции;
- назначенный `TASK_ID`, лимит/класс квоты, владелец;
- локальный worktree и состояние изменений (если доступны);
- что разрешено делать и что требует координации;
- статус `READY`, `READ_ONLY` или `NO_REPO_ACCESS`.

Не начинай постоянную фоновую работу и не обещай непрерывные изменения без нового задания. Продолжай текущую задачу до её handoff, затем жди следующего назначенного `TASK_ID`.
