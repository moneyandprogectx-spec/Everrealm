# Правило хранения материалов EVERREALM

Основное рабочее пространство EVERREALM — последний подключённый GitHub-репозиторий **[moneyandprogectx-spec/Everrealm](https://github.com/moneyandprogectx-spec/Everrealm)**. Актуальный репозиторий проекта проверяйте по подключению и адресу `git remote -v`; не подменяйте его одноимёнными старыми репозиториями.

## Что хранить в репозитории

- Поддерживаемые исходники, игровые данные, оригинальные модели и текстуры, документацию проекта, задачи, решения, реестры и handoff-файлы.
- Значимые изменения и результаты работы фиксировать в Git в отдельной ветке задачи, затем передавать на проверку через обычный процесс проекта. Не считать локальные файлы единственной копией результата.
- Общие промпты и инструкции для Codex, Claude Code и других агентов, относящиеся к проекту, хранить в репозитории рядом с соответствующей документацией и включать ссылки на них из главных инструкций.

## Экономия места на компьютере

- По возможности работать непосредственно с актуальным checkout репозитория и использовать Git для передачи изменений между машинами и участниками.
- Не создавать дополнительные полные копии больших исходных деревьев или архивы без необходимости. Для экспериментов использовать отдельные ветки и временные файлы; после проверки сохранять нужные результаты в проекте и удалять только собственные временные файлы.
- Большие производные сборки, кэши, временные рендеры и повторяющиеся ZIP-архивы не добавлять в Git без проектной необходимости. Для тяжёлых файлов выбрать явно согласованное внешнее хранилище и добавить в репозиторий устойчивую ссылку и описание.
- Не удалять и не перезаписывать общие или чужие локальные материалы автоматически. Перед очисткой проверить, что они сохранены в Git или другом утверждённом хранилище.

## Ограничения

- GitHub не заменяет резервную копию для секретов, локальных настроек и больших файлов, которые не должны попасть в репозиторий. Не загружать токены, пароли, приватные ключи, личные данные, защищённые сторонние игровые ресурсы и материалы с неподтверждённой лицензией.
- Соблюдать правила проекта о ветках, постоянных ID блоков, Godot/Voxel Tools, лицензиях и проверках. Эта политика хранения не разрешает прямые изменения `main`, публикацию, установку или удаление ресурсов, если такие действия не разрешены отдельными правилами или задачей.
- Если подключённый репозиторий недоступен, не заявлять, что изменения синхронизированы; сохранить работу безопасно и сообщить, что требуется для восстановления доступа.

## Передача результата

Для каждой существенной задачи обновлять соответствующие документы проекта и handoff: что изменено, где находится, какие проверки реально выполнены, что осталось и как продолжить. Указывать путь и ветку/коммит, чтобы следующий участник мог восстановить контекст из репозитория, а не из истории чата.
